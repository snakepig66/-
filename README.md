摘  要
近年来，随着物联网以及边缘计算技术的发展，生鲜零售行业正逐步走向数字化时代，在农贸市场、便利店等下沉环境下，传统的电子秤已难以满足现代化发展的需求。针对这种情况，本文提出一种基于FreeRTOS操作系统的智能视觉称重系统。
该系统利用双ESP32-S3进行分布式部署，基于FreeRTOS的多任务调度实现数据称重、网络通信、图像上传、人机交互等任务，从而极大地提高了系统稳定性；在核心算法部分，通过摄像头获取图片实时调用阿里云的千问多模态模型分析计算得出识别结果。经过联调测试，系统平均识别准确率达到91%，单次识别时间小于两秒，且所有数据成功通过MQTT协议上传到云端服务器。该系统对农产品零售终端的智能化改造有良好的推广价值。
关键词：双主控架构；智能计价；图像识别；FreeRTOS；物联网

基于RTOS的智能视觉称重系统
1  引    言 
1.1 研究的背景及意义 
新质生产力是以创新驱动发展为导向，用数字技术、网络技术和智能技术对传统生产要素进行重新配置，从而大幅提高全社会全要素生产率[1]。在此大背景下，传统的零售业数字化已是“势在必行”，而占据生鲜流通总量七成以上的农贸市场和社区生鲜店更是如此，它们的智能化改造对于整个农产品流通环节以及老百姓的生活水平都有巨大影响[2]。
物联网是新质生产力的重要组成部分，在过去十多年中技术的不断进步以及应用场景积累使它具有较为完善的端到端的产品形态。从感知层的各种类型传感器融合，到网络层的低功耗广域网连接方式，再到应用层的云端大数据处理及展示，IoT（物联网）技术栈的成熟使得传统的设备可以很容易实现智能化[3]。根据工信部数据显示，截至2024年底，中国蜂窝物联网连接数超过数亿，而NB-IoT和Cat.1模组在智能表计、新零售等领域的大规模商用也证明了低成本大连接是可行的商业模式[4]。
但是，在生鲜零售终端这样一个小领域内，技术应用程度和范围还有很大差距。传统的电子秤是市场、菜摊上最基本的称量设备，它只有“称重+单价计算+金额显示”的作用，商品编号要靠人记，交易信息也是存放在本地，不能帮助商家进行有效的经营管理，也不能让年轻人方便快捷地付款、明码标价的需求得到满足[5]。而我国市场上智能秤普及率不高，传统的电子秤依然有很大的市场占有率，这与整个智慧城市的发展水平形成了巨大的反差。
伴随着深度学习算法不断进步以及计算资源日益丰富，机器视觉已经从实验室走向大规模应用，在目标检测方面，以YOLO为代表的一类单阶段检测器可以在一次前向传播过程中同时实现目标定位及分类，在速度和准确性上取得良好折中[6]。近年来，像GPT-4V、Qwen-VL等多模态大语言模型具有出色零样本视觉理解能力，它们可以将图片转化为视觉Token并将其与文本语义空间进行匹配，因此可以通过简单的自然语言指令来回答开放性视觉问题而不需要针对具体商品进行微调训练[7]。这为“通用型视觉识别”提供了一种可能思路：终端只需要进行拍照并将照片发送到服务器上，繁重的工作都是由部署在云端的大模型来完成，这就避免了受限于本地硬件条件，从而实现“小设备+大模型”的方式[8]。
目前市面上商用智能收银解决方案大多采用“安卓工业主板+大尺寸触控屏+本地NPU”的叠加方式，一台机器的价格在1000到2000元左右，而一些日均营业额仅几百元的社区生鲜店或者菜市场的小商贩来说，投资回报率太低[9]。另外，从整体上来看，现有的方案存在致命问题：图像处理、称重获取、联网、屏幕显示等工作都在一个进程中进行，没有对各个任务进行有效分离以及合理安排各自的优先级，如果云上检测花费时间较长，则会使得前端页面出现卡顿或无法响应的情况，影响用户的购物体验。因此本文设计了一种基于实时操作系统（RTOS）的分布式嵌入式架构方案，利用两个不同核心的任务分配和云端视觉大模型的合作，在不影响称重及时性和识别精度的基础上降低成本到原有方案的十分之一，推动下沉市场的零售终端智能化发展。
1.2 国内外研究现状 
国外对智能零售硬件的研究及应用起步较早，技术路线以高端化路线为主。2016年，Amazon上线Amazon Go无人便利店，利用天花板上安装数百个摄像头以及深度传感器，配合计算机视觉、传感器融合以及深度学习等技术，可实现“拿了就走”的无感支付购物方式[10]。而该系统背后是大量使用云服务支撑其后台的行为检测及商品匹配等工作，单个门店的技术投入估计高达百万元人民币以上，由于技术壁垒过高以及高昂的成本，因此无法普及至小规模市场中。
在嵌入式操作系统领域，对于多核微处理器实时调度问题的研究已取得一定成果。基于混合调度方法、以及修改共享资源访问优先级，能够在一定程度上保证多个任务在资源有限的环境中同时执行[11]。但是这些工作大多数仅限于仿真实验或原型实现，缺乏对实际应用环境考虑，而且也没有充分考虑到成本因素带来的工程实现问题。
在商用智能称重设备方面，欧洲及日本市场主要使用ASIC芯片以及高精度电磁力传感器实现高精度测量（可达0.01 g量级），但售价一般都在5000元以上且软件生态封闭，主要用于大型商超或者工业计量等领域[12]。而这种方案不能满足我国下沉市场的“低成本、易维护、可定制”的需求。国内智能零售硬件发展具有“应用牵引、快速迭代”的特点，在移动支付普及推动下，技术方案迅速向低成本、高集成度方向发展。从操作系统来看，FreeRTOS因为其开源免费、内核精简、调度性强等原因在国内嵌入式开发者中被广泛采用。而在工业监控领域，FreeRTOS的任务并发能力可以保证传感器数据采集周期性和中断处理及时性，在任务上下文切换上几乎可以做到零成本[13]。对于低功耗设备而言，FreeRTOS的Tickless Idle模式联合事件驱动方式可以使MCU处于空闲状态时功耗大幅下降两个数量级从而大大延长基于电池供电设备的使用寿命[14]。
从硬件平台选择来看，乐鑫科技推出的ESP32系列已经成为中国物联网开发的标准配置，而更先进的ESP32-S3则是这个系列中的新产品，它具有Xtensa LX7双核32位处理器、2.4 GHz WiFi以及Bluetooth 5双模射频、外扩PSRAM接口，在仅售25元的情况下提供了远超传统8位或32位单片机的强大算力以及联网能力[15]。国内一些开发者已经利用ESP32-S3实现智能家居控制屏、工业HMI终端以及便携式医疗器械等产品的规模化生产，而且其开发工具（ESP-IDF/Arduino）文档丰富并且社区活跃，有利于快速进行原型设计。
在称重传感技术上，采用HX711专用ADC芯片方案已在我国电子秤领域占统治地位，在HX711中集成了低噪声可编程增益放大器及24位Σ-Δ型ADC，差分输入能很好地排除共模干扰，结合悬臂梁式压力传感器以及温度补偿方法，可以达到0.1 g的精度，完全可以满足商用计价秤0-5 kg量程，±5 g误差的要求[16]。而卡尔曼滤波、滑动平均滤波等数字信号处理方法的应用也提高了称重时的稳定性[17]。
在人机交互以及网络通信上，我国学者也取得了大量研究成果。基于离线语音识别芯片控制台，在无须连接互联网的情况下能够实现对固定词组进行本地化识别，响应时间小于500毫秒，在噪音环境中快速操作[18]。而在物联网中应用广泛的一种轻量级发布/订阅的消息传递协议是MQTT，其报文头只有两个字节大小，比使用HTTP时需要经过的TCP三次握手以及大量的报文头传输要节约大约90%以上的网络带宽，非常适合用于资源有限单片机的数据上传到云端[19]。综合以上国内外相关研究工作可以发现目前还存在以下问题：
第一，系统架构碎片化。大部分的研究都把重点放在单一功能模块的优化上面，例如仅仅去提高称重的精度，仅仅去改善图像识别的算法或者仅仅去做云平台数据的展示这样的情形，缺少对于“称重-识别-计价-上云”整个流程的系统性的整合。特别是有关在单个嵌入式系统当中协调实时任务和非实时任务的资源竞争，像“图像处理使得称重出现卡顿”或者“网络阻塞造成界面出现死机”这一类问题，还没有形成成熟的工程方面的解决办法。
第二，成本与性能这两者之间存在一种失衡的状况。现在存在的智能秤的方案，有的是运用高性能工控处理器来保证体验，但是成本比较高；有的是采用低成本单片机但是功能被大幅度阉割，缺少在150元级别的硬件成本限制之下实现“实时称重+ AI视觉+物联网”全功能闭环的典型事例。
第三，云端进行协同深度不足。伴随多模态大模型的能力不断提升，“端-边-云”协同的构架变成了边缘人工智能的关键演进方向，可是当下嵌入式系统的研究大多还处于本地推理或者简单的HTTP数据上报的层面，对于在内存小于8MB，无操作系统或者是轻量级RTOS的设备上，如何去实现和云端的LLM进行高效的交互，缺少有针对性的协议设计以及工程方面的优化。
针对上述研究缺口，本课题的核心定位在于：设计并实现一套基于FreeRTOS的低成本智能视觉称重系统，以双ESP32-S3分布式架构为硬件基础，以多任务实时调度为软件核心，以云端多模态大模型为智能引擎，在150元级硬件成本约束下实现毫秒级称重响应、秒级视觉识别、实时数据上云的全功能闭环，为中小微零售场景的数字化转型提供可复制、可推广的技术范式。
1.3 研究内容
本课题以双 ESP32-S3 微处理器作为主要硬件设备，配备高精度称重传感器、串口摄像头、离线语音模块以及能够连接多个物联网平台的功能，在此基础上开发一款具有实际用途的智能计价秤并对其进行一系列的功能测试与性能评价等。具体工作有以下几个方面：
（1）硬件电路设计与 PCB 实现
完成 ESP32-S3 最小系统电路图绘制，合理分配 I2C、SPI、UART 等外设引脚；完成 HX711 称重模块、ST7789 LCD 显示屏、4×4 矩阵键盘、ASRPRO 语音模块、MicroSD 卡存储、QMI8658 姿态传感器、HC-SR501 人体红外传感器等外设连接以及相关通信协议匹配；完成两层 PCB 电路板制作、生产和焊接测试，在此过程中主要解决模拟信号地（AGND）与数字信号地（DGND）的单点接地分离、WiFi 射频天线开放空间要求、供电方面问题。
（2）嵌入式多任务软件架构设计
在主控端移植 FreeRTOS 实时操作系统，实现多任务并发：把称重数据获取、矩阵键盘读取、WiFi 连接维护、LCD 显示、云上 AI 检测请求、MQTT 数据发送等功能分散到不同的任务中；由于 ESP32-S3 具有两个处理器，所以把对时间敏感的任务分配给核心 1，而把需要大量计算或者频繁进行网络交互的任务安排在核心 0上；使用 FreeRTOS 中的互斥量、信号量来保证共享资源的安全使用以及各个任务之间的协调工作。
（3）双模式计价与视觉识别功能实现
设计自动识别模式及手动输入模式两种计价方式，在自动模式中，视觉协处理器使用 OV5640 摄像头获取商品图片并进行 JPEG 压缩后经由高速串口传入计价主机，在主机上 PSRAM 中开辟空间存储该图片，对其进行 Base64 编码然后以 HTTP POST 的方式提交给阿里云百炼 Qwen-VL 多模态大模型 API，从返回结果中提取出商品名称，在本地 SD 卡的价格表中查找对应的单价从而实现自动计价，在手动模式中，用户可以通过矩阵键盘或者语音命令直接设定单价来保证网络出现问题或者是某些特殊商品时也能正常使用。
（4）人机交互与多模态控制功能完善
利用 LVGL 图形库开发一块 2.4 英寸 LCD 屏显示页面，有上方的状态栏、中间的数据卡片、下方的价格总额以及可移动的输入光标；进行矩阵键盘的 16 个按键扫描及去抖动操作，设置数字键、功能键对应关系；加入 ASRPRO 离线语音模块，从 UART2 串口读取识别内容，“去皮”、“切换模式”、“确认价格” 等语音控制操作。
（5）物联网通信与数据上云功能开发
通过 ESP32-S3 内置 WiFi 射频，在 STA 模式下连接 WiFi 并进行断线重连；使用 PubSubClient 库实现 MQTT 协议栈，连接到 OneNET 和 EMQX 两个平台；根据 OneNET 物模型要求编写 JSON 格式的数据包，实现交易数据周期上报以及对远端设备进行控制。
（6）低功耗与安全防护功能开发
利用 HC-SR501 人体红外传感器实现工作状态监测：无人存在三十秒之后自动进入休眠状态，关闭不必要的设备，使得待机电流减少至原来的五分之一甚至更低；有人靠近一秒钟之内迅速唤醒，恢复正常的工作方式。利用 QMI8658 六轴传感器实现秤体倾斜检测：不断计算出俯仰角以及横滚角，一旦倾斜角度大于等于正负五度就发出报警信号，避免由于地面不平整造成测量结果错误。
（7）整机联调与性能测试验证
对完成组装的实物样机进行系统化功能测试：使用标准砝码进行称重精度校准测试；选取常见果蔬在不同场景进行视觉识别准确率测试；测量自动计价全流程响应的时间；进行 24 小时连续运行稳定性测试，监测 FreeRTOS 任务堆栈剩余空间与内存碎片情况；进行人为断网下自恢复测试，验证 MQTT 自动重连与数据缓存机制的有效性。
2  总体设计方案 
2.1 概述 
本章节是有关系统的整体设计方案，首先对依托于RTOS的智能视觉称重系统开展全面的说明，清楚地划定系统设计的位置，核心架构，硬件组成，软件框架以及核心功能，以此为后续的硬件电路设计，软件程序开展，系统调试和测试提供整体的设计依据。
本系统把农贸市场、社区生鲜店这类生鲜零售下沉市场的需求作为核心关注的要点，针对传统电子秤存在功能单一，操作繁杂的情况，以及现有智能视觉秤成本过高，难以进行推广的痛点，采用双ESP32-S3分布式主控架构来进行运用，搭载上FreeRTOS实时操作系统，整合高精度称重采集，云端多模态视觉识别，多模态人机交互，物联网数据上传，低功耗控制与姿态防护等技术，研发出来一款具有低成本、高实时性、易部署特点的智能视觉称重终端。
系统硬件把两片ESP32-S3微控制器作为核心，分别作为计价主控以及视觉协处理器，外接HX711称重传感模块，OV5640图像采集模块，ST7789LCD显示模块，4×4矩阵键盘，ASRPRO离线语音识别模块，SD卡存储模块，QMI8658姿态传感器模块，HC-SR501人体红外传感器模块，依靠UART，SPI，I2C等通信接口来实现各模块数据交互以及协同工作，同时运用数模隔离，天线净空区设计，电源滤波等方法来保证硬件运行的稳定性。
系统软件是依靠FreeRTOS来构建多任务并发调度的框架，将称重数据采集，图像传输与编码，云端AI识别，LCD界面刷新，WiFi连接管理，MQTT数据上传这些功能分解成为独立的任务，按照实时性优先级分配到双核心来进行运行，以此来防止单任务出现阻塞导致系统出现卡顿的情况；采用“终端采集+云端识别”的模式，调用阿里云百炼Qwen-VL多模态大模型来达成商品的自动识别，匹配本地SD卡的价格表来实现自动计价，同时保留手动计价的模式，保证在网络异常的场景下能够正常使用；通过MQTT协议来实现交易数据往OneNET，EMQX双云平台的实时上传以及远程查看，整合人体感应低功耗待机，秤体倾斜报警的功能，进一步让系统的实用性和安全性得到增强。
本系统以低成本、高实时性、功能完整、易维护为核心设计目标，整机硬件成本控制在百元级，可实现称重、识别、计价、上云全流程自动化，为传统生鲜零售终端的智能化改造提供轻量化、可推广的技术方案。
2.2 系统设计要求
（1）称重精准度情况：系统进行重量读取的时候状态稳定，去掉皮重的时候响应速度比较快，在0到5 kg这样的量程区间范围之内，误差把控处于常规商业所允许的范围当中。
（2）对于图像处理以及内存管理方面的情况：因为一幅JPEG格式的图像通常会占几十KB大小的内存，系统得具备合理的内存管理的机制，在接收图像还有对图像进行编码的时候，需要保证单片机不会因为内存耗尽出现死机重启的状况。同时云端进行识别的整个过程不可以耗费太长的时间，应控制在合理范围内，保障用户的体验。
（3）容错以及双模式运作的情况：系统应该具备“自动识别”与“手动输入”两种模式。当网络信号处于不佳的情况或者遇到不能被识别的特殊商品的时候，用户能够快速地切换到手动模式去输入单价，保证不被设备出现的故障给影响到。
（4）支撑本地价格表进行更新：系统应能够读取外置的SD卡当中的表格文件，实现云端返回的商品名称和商家自己设定的单价之间的对应，并且方便商户随时借助电脑对价格进行更改。
（5）运行流畅性方面：重量数据进行实时更新，屏幕界面进行刷新以及后台网络进行心跳保持等动作得独立运行，不能因为网络延迟而让称重数字出现卡顿状况。
（6）数据上传格式的规范：把数据向OneNET平台发送的时候要严格依照这个平台物模型JSON格式要求来做，保证云端可以正确地进行解析并且展示交易的重量以及总金额。
（7）姿态异常防护情况：系统会实时对于秤体的水平状态进行监测，当X轴或者Y轴的倾斜角度超出正负5度的时候，屏幕上就马上出现秤体倾斜的提示；而当倾斜角度恢复到正负1度以内的时候，就会自动解除报警并且恢复正常称重情况。
（8）低功耗的待机状况：系统利用人体红外传感器对使用的状况进行实时监测，当没有人员的状况持续三十秒之后自动进入待机的模式，关闭不必要的外部设备；一旦检测到有人体靠近，系统能够在一秒之内迅速唤醒，恢复所有的功能。
2.3 设计思路 
本系统的软件设计没有使用传统单片机开发中常用的“大循环”裸机开发模式，而是引入了 FreeRTOS 实时操作系统。实时操作系统最大的优势在于其极高的实时性。可以精准响应和调度每个预设的任务，不会出现堵塞的问题。
基本思路是把耗时较长或者需要后台静默运行的任务（比如网络重连、LCD 屏幕定时刷新、MQTT 数据上传）提取出来，分配给 ESP32-S3其中一个核心作为独立线程运行；另一个核心主要负责处理对实时性要求较高的中断或轮询任务，比如按键扫描和语音串口的数据接收。
当设备处于“自动识别”模式，一旦主控在串口发来的图像帧头，就会马上在 PSRAM 中动态申请一块大内存来存放图像的数据，同时马上原地开始性能要求高的 Base64 编码。由于高效的实时操作系统的任务调度，后台的屏幕显示和重量读取依然在正常执行。这种模块化协同的设计可以保障设备能够流畅运行。
2.4 系统方案的论证  
2.4.1 主控芯片的选择  
为了满足大容量图像处理和物联网通信的需求，本次设计对主控芯片进行了对比考量：
方案一：选用 STM32H7 系列高性能单片机。该芯片主频较高，具备较强的外设扩展能力。但其要外接 WiFi 模块才能联网，这增加了硬件复杂度；而且H7系列芯片成本偏高，内部 SRAM 容量有限，如果要缓存大图还需外挂 SDRAM，和本设计低成本的初衷不太相符。
方案二：选用乐鑫 ESP32-S3 单片机。该芯片自带 2.4 GHz WiFi 和蓝牙功能，省去了通信模块设计连接；它支持外接大容量 PSRAM可以轻松处理 JPEG 图片的缓存需求；更重要的是它的板子硬件价格非常低，二十元的单价内嵌WiFi和蓝牙，官方提供的开发文档也非常丰富，网上开源资料很完善，社区资源也丰富而且用户量大。
综合考虑芯片算力、网络集成度以及硬件采购成本（STM32H7 单芯片成本约 80 元，ESP32-S3 约 25 元），本系统最终选择方案二，使用 ESP32-S3 作为核心控制器，并决定采用双 MCU 的物理架构。
2.4.2 称重采集模块方案选择  
方案一：直接利用单片机自带的 ADC 引脚采集压力传感器输出的模拟电压。这种做法虽然节省了元件，但由于传感器在形变时产生的电压变化极微小（毫伏级），单片机内部 ADC 容易受到外部电磁干扰，会导致换算出来的重量数字发送剧烈跳动，会无法满足称重的精准性，同时还难以满足商用需求。
方案二：采用专用的 24 位模数转换芯片 HX711。HX711芯片内部集成了低噪声放大电路，能将传感器的微弱信号放大后再进行高精度的数字化处理，主控单片机只需要通过两根普通的 GPIO 引脚就能稳定读取数据，也不用自己写过于复杂的滤波算法。
考虑到计价秤对称重精度的严格要求，本设计选择方案二。
2.4.3 图像识别模块方案选择  
方案一：使用基于K210芯片边缘计算视觉系统，通过内部集成的NPU完成本地化离线推理任务，具有较低延迟且无需连接网络等优点，但是由于高昂的价格以及较小内存限制了更大更复杂模型的应用以及对不同物品识别能力。
方案二：基于双MCU分布式构架以及云计算技术设计而成。其中，ESP32-S3负责大部分视觉信息获取工作，利用DVP接口连接摄像头。拍摄完毕后以JPEG形式存储在Flash中并通过高速UART（波特率设置为921600bps）传送到主控MCU上然后将对该图片进行分析请求发往云服务器。这样可以大大减轻主控负担。
论证结果：从系统的使用感受以及模型识别精度上考虑，本文采用方案二。
2.4.4 交互终端与图形界面方案选择
方案一：该方案基于Android开发触摸式串行通信显示屏。其主要优点是良好的显示效果以及方便快捷的操作方式，但是由于每块屏幕的价格一般超过一百元，而且开机较慢、功耗较高，不符合我们希望做到轻量化的理念。
方案二：系统交互界面是基于 LVGL的 2.4 寸高分辨率彩色 LCD 。屏幕显示逻辑采用数据同步镜像的机制：计价主控端计算得出实时重量与金额后，把其封装为 JSON字符串，再通过主控的GPIO 1 串口发送到视觉终端。视觉终端解析 JSON 后，把数据写入 LVGL 标签对象进行帧率为10 hz的刷新，还加入了模拟光标闪烁效果，手动输入单价时的交互体验提升很明显。
论证结果：综合评估硬件成本和实际使用场景需求，本系统选择方案二。
2.4.5 数据上传通信方案选择 
方案一：使用传统的HTTP轮询方式把交易信息传输到私有服务器上，在此方式下实现较为简便，但是每次都需要新建一个TCP连接所带来的开销较大，而且实时性比较差。
方案二：基于长连接以及MQTT协议完成与OneNET物联网平台之间的通信，在与传统的HTTP协议对比中，MQTT有更小的消息体积以及更好的网络带宽利用的优势，通过使用JSON格式的物模型，可以保证一秒一次的心跳以及消息发送的需求，进而提高整个系统的性能并减少资源浪费。
论证结果：由于受到资源限制单片机带宽开销以及通信可靠性问题，在此我们采用方案二。

3  硬件电路设计 
3.1 系统硬件整体设计
本系统的硬件电路双 ESP32-S3 分布式架构，由主控板与视觉子系统板两个独立的核心板组成。主控板向外连接 HX711 称重模块、4×4 矩阵键盘、ASRPRO 语音识别模块、SD 卡存储模块和HC-SR501 人体红外传感器；视觉子系统板连接 OV5640 摄像头、2.4 寸 ST7789 SPI 显示屏及 QMI8658 姿态传感器。两块核心板通过高速串口（921600bps）进行通信，可以高速完成图像数据和称重数据全双工通信。
系统运行时，5V 直流电源使用 type-c 给系统稳定供电。计价主控使用 GPIO4 和 GPIO5 接收HX711 传感器的模拟称重信号，用 8 个 GPIO 引脚连接矩阵键盘，通过SPI 总线挂载 SD 卡读取分析商品价目表，GPIO45用来接 HC-SR501 人体红外传感器实现待机唤醒控制。系统有两个不同的 UART 串口：一个可以快速传送图片数据，另一个与语音识别模块通信。

3.2.2 HX711 称重传感器模块电路

3.3 PCB 设计
PCB 板采用二层板布线，长宽都为10 cm。在将原理图转化为印刷电路板的过程中，布线规则和电气隔离还有铺铜区域会直接影响到称重数值的稳定性，PCB设计图如图3-10所示。制作 PCB 时主要注意到了以下几点：
（1）数模隔离与接地处理
HX711 模块在采集微小电压时容易受到 ESP32-S3 射频信号和高速串口的干扰。所以在器件布局时，悬臂梁接口和 HX711 芯片统一放在电路板边缘；在铺铜时，将模拟地与数字地独立铺铜，两块地平面仅在电源输入端通过0Ω 电阻连接，以此减少地弹噪声。
（2）天线净空区设置
由于主控 ESP32-S3 模组自带板载 PCB 天线。在进行顶层和底层的敷铜操作时，在模组天线正下方以及周边大约 5mm 的区域内设置了净空区，未敷设任何铜皮和信号线。这能尽量避免金属平面吸收 2.4 GHz WiFi 信号，可以保障图片上传时的网络连接质量，可以避免吸收到杂波干扰。
（3）电源走线与信号完整性
由于 WiFi 发射瞬间电流比较大，主干 3.3 V 电源线的铜线宽度设置在 20 mil，并在各个模块的 VCC 引脚附近放置了 0.1μF 的陶瓷电容。对连接 SD 卡的 SPI 总线和连接摄像头的 UART1 接口，在走线时尽量保持数据线与时钟线进行等长布线和平行布线，减少过孔的数量，降低电容电感对高频信号的影响。

4  软件程序设计 
4.1 软件开发环境和计算机语言介绍 
本系统的软件程序是在基于VScode的PlatformIO开发环境下面进行编写的，而且在底层调用了ESP-IDF框架的相关应用程序编程接口。PlatformIO拥有数量众多且完善的外设驱动库，可以快速地达成对传感器的适配。系统底层软件采用C++语言进行编写。
在第三方的扩展库相关的范围之内，程序调用了对应的文件从而来实现MQTT协议。在外部设备这一部分，封装了对应的库整合用来驱动传感器和显示屏。为了达成在单片机上面大容量图像的编码，程序引入了底层的高性能编码库，显著提升了编码速度。
4.2 主程序设计 
主程序主要由初始化函数和循环函数构成。
在初始化函数阶段，系统首先以 115200 bps 的波特率初始化调试串口，并分别用 9600 bps 和 921600 bps 的波特率配置连接语音模块的串口和接收图像的串口。程序按顺序执行外设初始化流程：首先点亮蓝色指示灯，初始化 LVGL 图形库和 ST7789 LCD 驱动并在屏幕上显示“系统启动中...”；接着，调用检测外部 PSRAM 是否正常挂载，如果挂载失败程序会进入死循环（因为后续的图像存储需要外部内存支持）；再初始化 HX711 模块，执行一次自动去皮；最后初始化 SPI 总线挂载 SD 卡，把价格表读取至内存中。初始化结束后，程序创建 3 个互斥锁，可以分别保护重量、单价、商品名称全局变量的读写安全，设置 100 ms 获取超时避免死锁数据错乱。
在主循环阶段，程序主要处理对实时性要求比较高的人机交互操作。通过高频轮询来捕捉获取当前的按键和语音指令，再根据当前的全局状态变量，可以精准的在自动识别模式和手动计价模式之间进行逻辑分支处理。如图4-1所示。

4.3 FreeRTOS 多任务管理程序设计 
由于系统需要同时处理称重采集、网络通信和屏幕显示等多个操作，若全放在单循环中执行，WiFi 重连或 HTTP 请求的延时容易导致称重读数卡顿。为此，本系统引入了 FreeRTOS 实时操作系统，设计了多个独立的后台任务，并分配至不同核心运行：
（1）主计价的循环：是在核心1进行运行。承担高频地采集HX711称重的数据，扫描键盘进行输入还有处理语音方面的指令这样的工作。
（2）WiFi管理方面任务：它的优先级被确定成为1，在核心0之上进行运行。此工作在后台对于网络连接的状态开展监测，针对断线的状况进行处理并且通过事件标志组去更新连接状态位。
（3）人工智能方面的异步识别任务：它的优先级是1，是在核心0之上进行运行的。是该系统核心进行优化的地方所在，依靠信号量去触发，在后台进行异步的处理那耗时的云端大模型方面的请求，这样可以做到避免主流程在进行识别的时出现死机以及卡顿的状况发生。
（4）LCD显示任务：把它的优先级设定成为2，因为LCD显示任务的优先级比WiFi任务的优先级要高，这样就可以保证界面的实时性，此任务是在核心0上面运行的。这个任务以一百五十毫秒作为周期去刷新屏幕画面，可以保证显示界面是连贯的，同时不会过多地占据系统资源。
（5）OneNET数据上传任务：把它的优先级确定成为1，并且这个任务在核心1上面进行运行。主要是承担维持MQTT客户端和云平台之间的心跳连接，且定时进行数据的打包以及进行稳定的上传的工作。
视觉子系统运行 2 个独立任务：
（1）数据接收任务：它的优先级是1，在核心0上面进行运行。负责接收从计价主控所发送过来的JSON数据，在对这JSON数据开展解析操作之后去对显示变量进行更新。
（2）IMU倾斜检测任务：它的优先级是1，在核心0上面进行运行。执行读取QMI8658这个姿态数据的工作，并且去判断是否会触发倾斜方面的警告。
在进行多任务运行这种情况的时候，为了防止显示任务和主循环任务同时对于商品名称，单价这些全局变量进行读取和写入从而引发数据冲突的现象出现，程序把互斥量Mutex导入进来。在对任何任务里面的这些关键变量进行更新操作之前，都必须首先去获取锁，在完成数据方面的操作之后释放锁，通过这样的方式来保证数据进行读取和写入时的安全性，多任务管理如图4-2所示。

4.4 称重数据采集模块程序设计
重量数据的获取逻辑封装在获取重量函数中。在读取数据前，会先判断 HX711 的 DOUT 引脚电平情况（是否为数据就绪状态）。考虑到硬件偶尔可能会出现响应延迟，程序内加了一个带有最大 5 次限制的微秒级超时重试机制。若是达到最大重试次数还未就绪，函数会返回 0.0 g的数据，避免主循环因等待传感器而发生死机。
系统还编写了去皮程序。当检测到矩阵键盘的 'B' 键被按下或者收到语音去皮指令，系统会调用把传感器当前读数清为零，同时在 LCD 屏幕上显示“正在去皮...”，操作结束后恢复正常界面，就可以继续使用，响应时间＜200ms。
4.5 图像识别模块程序设计  
图像处理与识别是自动计价模式的核心功能，主要包括本地数据接收和云端接口调用两部分。
4.5.1 图像数据接收与处理程序设计 
视觉采集模块获取的原图数据进行JPEG压缩之后，在921600 bps波特率下通过串口将这些数据传输到主机上，在主机全自动化状态下，主机上的主要程序会读取串口缓存区的数据，如果发现了一个预定的起始标记，那么就意味着一个完整的数据包已经到来，接下来就可以开始接收并处理该数据包里面的各项信息。
在解析帧头之后，解析模块读取四个字节表示图像大小，然后使用函数从外部PSRAM中动态地申请相应大小的一块连续空间来存放接收到的图像数据，在完成操作之后，在帧尾处加上一定的标志位进行帧完整性的检查，如果发现帧尾的检查失败或者串口超时或者内存不够等情况，则会进入错误处理流程：先释放之前分配的空间，再清除串口缓冲区剩余内容，这样既可以防止可能出现的内存溢出问题，也可以提高程序鲁棒性和健壮性。
4.5.2 Base64 编码程序设计 
当一张图片上传到服务器上时需要把原图的数据转化为Base64格式的数据。由于单片机的硬件条件较差并且计算能力不足，所以使用传统的字符串拼接的方法是无法进行高效的操作。因此这里利用ARM平台上的编码函数来进行快速编码的操作，在初始化的时候传入NULL来获取要写入的缓冲区大小然后在PSRAM中分配相应大小的空间用来进行编码工作，在编码完毕之后立即释放掉已经不再使用的内存以防止出现内存泄漏而造成整个程序的崩溃。
4.5.3 千问大模型 API 调用程序设计 
成功完成图像的Base64编码后，程序会调用识别函数，在阿里云兼容的服务端点发起一个POST请求进行预测，在请求体中以OpenAI API格式组织一个包含目标图片Base64编码以及一个可选提示信息（如：“从这张图片中识别出蔬菜水果的名字并且用一个字符表示，不要有额外描述信息”）。为了保证服务响应速度，程序设置了一个10秒钟的超时时间来提升用户体验。
从服务器接收到JSON格式字符串之后，程序利用解析函数对它进行解析，在解析得到的数据结构中，消息对象下的“content”对应的即为大模型给出的商品识别结果，找到商品名之后，在内存的价格列表中找到对应的商品并从中读取价格信息，然后更新这个价格到显示在LCD屏幕上的全局变量中如图4-3所示。

4.9 姿态检测程序设计
系统上电后，视觉处理器调用函数完成传感器初始化：配置 I2C 通信速率为 400 kHz，设置加速度计量程为 ±2 g、陀螺仪量程为 ±250 dps，开启数字低通滤波器（截止频率 20 Hz）。开机后静置 1 秒，采样 20 次取平均值作水平基准零点，消除静态零点误差。
姿态数据读取封装在独立任务中，以10 Hz频率读取加速度计数据，计算当前倾斜角度。当最大倾斜角度超过 5°时，标志位反转，屏幕立即显示：请放平秤体！警告，当倾斜角度恢复至 ±1°以内自动解除警告。
4.10 人体检测程序设计
人体检测在计价主控的主循环中以 200 Hz 频率轮询 GPIO45 的电平状态：检测到高电平时，立即更新当前系统时间；如果系统正处于待机状态，会触发唤醒流程。
检测到低电平时开始计时，超过 30 秒阈值则触发待机流程：首先置位全局标志位，通知所有后台任务切换到低功耗状态；最后主循环跳过称重采集、图像识别、键盘处理等所有业务逻辑，只保留 200ms 一次的人体检测轮询，可以大幅降低 CPU 占用和系统功耗。

4.11.4 独立任务设计

任务2：以读取 QMI8658数据，计算倾斜角度判断是否触发倾斜警告。任务运行于核心 0，不会影响主循环的界面刷新。

6   总    结
为了应对传统生鲜零售及农贸市场中存在传统电子秤结算速度慢、容易出错，现有的人工智能秤价格昂贵、小本经营者无力承担的问题，在此提出了一个基于FreeRTOS实时操作系统的低成本智能视觉称重方案。方案采用双ESP32-S3微处理器作为主控芯片，集成了计算机视觉、物联网以及多种人机交互方式于一体，实现了对商品进行检测、称重计算价格并上传至云端的整个流程，对于下沉市场的零售终端设备智能化具有良好的借鉴意义。
从硬件方面来说，采用计价主控+视觉协处理器的分布结构，在根本上解决了一体化主控带来的图像处理造成称重延迟的问题。设备配有HX711高精度称重传感器、OV5640摄像头、ASRPRO离线语音模块、QMI8658姿态传感器等外部器件，利用数模隔离单点接地、天线净空区设置以及电源滤波等方式减少电磁干扰的影响，保证称重准确性和无线网络连接稳定性。全机主要元器件费用大约为150元，而市面上同类型Android架构智能秤价格大多在1500元左右，成本极大降低。
软件设计上，摒弃传统的单片机裸机的大循环开发方式，在FreeRTOS的基础上搭建开发，把WiFi管理、LCD显示、AI识别、MQTT数据上传等功能各自作为一个任务分布在不同的内核中执行，用互斥量保证整个系统的安全性以及正常运行。主要功能上，该系统使用阿里云百炼Qwen视觉大模型API进行果蔬商品的自动识别以及价格匹配，可以做到自动识别和手动输入之间的自由切换；用矩阵键盘以及离线语音模块实现了削皮、模式切换等多种操作方式；通过MQTT协议将交易信息发送到OneNET及EMQX两个服务器上，还具有人感低功耗休眠、秤体倾斜报警等功能。
经过一系列测试及功能测试，本系统各项技术指标均达到要求：0～5 kg全量程称重误差不超过±4 g，在各种不同光照条件下对商品识别总准确率为91%，每次平均识别速度为1.8 s，全天候不间断工作不会出现卡顿或者内存溢出的问题，断网后十秒钟以内可以自动重新连接上网络。在使用过程中，该系统简单易用，用户体验良好，在一定程度上提高了生鲜零售行业收银的速度同时也减少了商家的人力资源以及学习成本。
本文亮点主要有三点：首先，提出了一种基于双ESP32-S3的分布式计算方法，在低成本条件下同时完成视觉识别以及实时称重任务；其次，提出一种资源有限单片机和云端大模型结合的方法，解决了嵌入式设备计算能力较弱的问题；最后，在生鲜市场应用场景下添加语音交互、低功耗待机以及防倾倒等功能，使产品更加实用。
目前系统尚有改进空间，在未来工作中将进一步完善云端价格批量下发功能以及在ESP32-S3上部署轻量化视觉 AI 模型以减少对网络的要求，使本方案能在更多小本经营户及农贸市场中推广使用。
